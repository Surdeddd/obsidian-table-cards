# Table Cards v3 — UX and Accessibility Audit

<!-- markdownlint-disable MD013 -->

Date: 2026-08-19

Standard: WCAG 2.1 AA plus a 44×44 CSS px coarse-pointer convention

Scope: setup, mandatory launcher, grouped table selection, study, exact-card browser, editor source route, long/empty/image states, Arabic RTL, and reduced motion

## Outcome

No open critical or major findings remain in the deterministic production-class fixtures. The release keeps one elevated surface per task, uses a strict monochrome hierarchy, and keeps source/table structure legible through spacing and hairline rules rather than decorative chrome.

The launcher's spacious middle is intentional: launcher, loading, error, selector, and study share one stable modal shell, so async state changes never move the confirmation footer or resize the session surface.

## Findings resolved

| Finding | Severity | Resolution |
| --- | --- | --- |
| A general command could jump directly into a remembered deck | Critical | Every path now stops at the mandatory launcher and requires **Open N cards** |
| A deck ribbon could imply immediate study | Major | Ribbon launches lock the deck but retain table selection and confirmation |
| Multi-table scope was hidden behind all/single source choices | Major | Grouped selectors expose file identity, selected/total counts, table labels, rows, columns, all/clear, and search |
| Mobile scope selection risked a nested popover | Major | Coarse pointers use one full-height sheet with sticky search and a direct-child Apply footer asserted against the viewport safe-area edge |
| Empty scope could produce an ambiguous blank session | Critical | Clear materializes an explicit empty scope, updates counts, explains recovery, and disables start |
| Loading and error states could shift actions | Major | A stable state region and fixed shell preserve footer position; retry retains deck/scope context |
| Search lacked exact source identity | Major | Results group by table and include primary value, snippet, file, table, and row before exact opening |
| Editor source controls exposed implementation-heavy choices | Major | Source cards now show path, kind, summary, warnings, Choose tables, and remove only |
| Table selection could stack another modal inside the editor sheet | Critical | The same sheet body switches to one focused route; Back restores the exact source opener |
| Arabic direction could leak into English user data | Critical | RTL is scoped to plugin chrome; card/source data containers use `dir="auto"` or explicit LTR fixture content |
| Locale counts were hard-coded | Major | Runtime uses cached `Intl.NumberFormat`; Arabic captures assert Arabic-Indic digits |
| Phone controls could fall below the target convention | Major | Automated geometry checks cover every visible button, summary, text field, and checkbox label at coarse-pointer viewports |
| Decorative canvas/setup gradients weakened the monochrome direction | Moderate | Removed the two decorative radial fields; functional chevrons and drag-grip marks remain |
| Static previews bypassed v3 behavior | Major | Root preview now starts at launcher; dedicated setup/launcher/study/editor fixtures use production classes and deterministic states |

## Accessibility and interaction checks

- Base launcher, setup, study, and editor dialogs plus browser, scope, lightbox, and mobile-selector dialogs trap Tab in both directions. Sheets expose accessible names, modal semantics, independently scrolling bodies, and visible focus.
- Escape closes the innermost listbox/scope/browser/image layer first and restores its opener; editor table Back restores the exact Choose tables action.
- Styled listboxes and grouped table controls use buttons, listbox/option roles, `aria-expanded`, `aria-selected`, `aria-pressed`, and labelled search inputs; targeted v3 fixtures contain no native `select`.
- General, desktop, and mobile grouped selectors implement group all/clear, global Clear, live table/card counts, disabled empty start, and Apply with opener focus restoration.
- Exact search-result opening changes the word, progress counter, table, and file to the selected source row before restoring the browser opener.
- Arrow keys, `S`, pointer swipe, image zoom, full-sheet Apply, editor route Back, and reduced motion are exercised by Playwright.
- Meaningful images have alt text; decorative glyphs are hidden or sit inside explicitly named controls.
- Arabic search, close, progress, shuffle, browser, and scope names use localized accessible text and Arabic-Indic digits while English card/source content keeps its natural direction.
- Every requested launcher, setup, and study fixture state is asserted visible and nonblank; empty, loading, error/retry, `S`, scope Apply, setup navigation/preset/icon/create, and the focused desktop selector are exercised.
- Representative 10–11 px faint labels are checked from computed foreground/background colors and meet at least 4.5:1.
- No tested fixture emits a console error/warning, requests an external asset, or creates document-level horizontal overflow.

Accessibility-tree snapshots are stored beside the screenshots in `docs/screenshots/a11y/`.

The standalone setup fixture exercises step navigation, preset preview changes, ribbon-icon selection, and the final create summary. Its Add file, Add folder, Choose tables, and remove controls are visual contract examples only: the real actions require Obsidian vault pickers/scans and are not represented as browser-tested interactions here.

## Intentional limitations

- No external row deep links: Markdown rows have no stable native identifier and can move or change.
- No spaced repetition, scoring, or statistics: Table Cards remains a focused renderer and browser.
- No cell editing: source Markdown stays authoritative and is never rewritten by the plugin.
- Browser rendering is capped at 100 mounted matches while the full match count remains visible.
- A physical-device VoiceOver/TalkBack speech and gesture-feel smoke test remains a release-device check; browser automation covers semantics, focus, geometry, and DOM behavior.

## Evidence and reproducibility

`npm run test:ui` starts a fresh local fixture server that refuses fixed-port reuse and identifies its repository root in a tested response header. It regenerates screenshots/accessibility snapshots and asserts viewport geometry, target sizes, focus trapping/restoration, state transitions, exact-result identity, localized accessible names, computed contrast, reduced motion, console cleanliness, external requests, native selects, and overflow. `npm run test:tools` verifies Markdown inline/reference/angled links and local anchors; `npm run typecheck:tools` and `npm run lint` cover the preview, tests, scripts, and configuration with environment-specific checks. The complete command log and screenshot dimensions are recorded in the ignored Task 12 SDD report.
